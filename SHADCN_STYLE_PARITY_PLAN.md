# lovdaCN shadcn Style Parity Implementation Plan

**Status:** Proposed for review; no feature implementation is included in this document.
**Repository:** `C:\Users\saima\OneDrive\Desktop\expo-ui\lvcn`
**Primary goal:** Make Shuffle visibly change component recipes, typography, icons, and layout density—not only colors, font family, and radius—while preserving lovdaCN's Expo/React Native architecture and generated-source model.

## 1. Executive decision

Implement the eight recipe-backed style families already represented by the vendored/generated shadcn assets:

- `luma`
- `lyra`
- `maia`
- `mira`
- `nova`
- `rhea`
- `sera`
- `vega`

Do not advertise `default` or `new-york` as separate styles. They currently have no recipe CSS and produce effectively the same base component output. Keep their old wire values and registry URLs temporarily for compatibility, but normalize both to `vega` in current UI/CLI behavior.

The implementation should use two forms of the same recipe source:

1. **Runtime preview:** a small React design-system context plus generated, NativeWind-safe static recipe maps so a preset update rerenders the iframe immediately.
2. **Installed output:** per-style static component and block source generated by the registry compiler, so a user's project receives only its selected recipe rather than all eight runtime profiles.

Retain three coherent cross-platform icon families after adapters are complete:

- Lucide: `lucide-react-native`
- Phosphor: `phosphor-react-native`
- Tabler: `@tabler/icons-react-native`

Remove Expo and Heroicons from active choices. `@expo/vector-icons` is an umbrella of unrelated families rather than one visual style, and Heroicons is not wired through the current preview, registry components, or block output. Legacy `expo` and `heroicons` preset values should normalize to Lucide.

Retain the six font families used by the eight named styles and implement them end to end:

- `inter`
- `dm-sans`
- `figtree`
- `space-grotesk`
- `playfair-display`
- `jetbrains-mono`

Hide the other currently encoded fonts until they have the same preview, native loader, template, weight, and generated-output support. Preserve their v1 wire values and normalize old presets by category.

The dedicated `/customizer-preview` route, stable iframe URL, `postMessage` update path, `lvcn:applied` acknowledgement, and `/present` isolation are non-negotiable constraints.

## 2. Scope

### In scope

- Style-dependent control height, padding, gap, density, border, radius intent, shadow, focus treatment, menu/list density, and card spacing.
- Style-dependent component typography: size, line height, weight, tracking, casing, and role-specific treatment.
- A lightweight runtime style resolver for the customizer preview.
- Runtime icon-library switching inside the customizer preview.
- A semantic icon registry with equivalent Lucide, Phosphor, and Tabler mappings.
- Cross-platform font loading for the retained fonts.
- Style-aware block layout where component recipes alone are insufficient.
- Static generated component/block output matching the preview.
- One canonical source for supported values, preset metadata, aliases, recipe assets, icons, fonts, and generated schemas.
- Removal of unsupported choices from pickers, randomization, prompts, current schemas, docs, and generated metadata.
- Backward decoding/migration for existing v1 preset codes and `lvcn.json` files.
- Type, build, visual, accessibility, generation-drift, and bundle-size validation.

### Out of scope

- A literal copy of shadcn's DOM-only body-class and CSS-cascade implementation.
- Shipping all styles, icon packages, or font packages into every generated user project.
- Maintaining eight manually duplicated dashboard components.
- Redesigning the customizer transport or replacing the optimized iframe.
- Refactoring the heavy `/present` application as part of this work.
- Converting arbitrary user-authored direct icon imports when the CLI cannot prove ownership.
- Adding dependencies before this plan is approved.

### 4.3 Compatibility contract

- Keep the v1 prefix (`a`) and its exact value ordering as an immutable decode table.
- Introduce separate active arrays; do not use the wire arrays for UI or randomization.
- Decode in two steps: `decodeWirePresetV1()` then `normalizePreset()`.
- For every active config, `decode(encode(config))` must equal the original config.
- A legacy code must decode to a documented active config; re-encoding it produces a stable normalized code.
- Existing `lvcn.json` legacy values are accepted by the CLI, migrated transactionally, and written back only after validation.
- Keep old `/r/styles/{engine}/default/*` and `/r/styles/{engine}/new-york/*` URLs for at least one published major compatibility window so older CLI clients do not break. Do not list them in the current style index.
- Current JSON schema enums should contain active values only. Legacy acceptance belongs in CLI migration code rather than continuing to advertise unsupported values in editor completion.
- Phosphor and Tabler must not be exposed in production UI until their full semantic icon coverage, bundle, and generated-output tests pass. An incomplete development phase may temporarily expose Lucide only.

## 5. Target architecture

### 5.1 Principles

1. **One canonical source, multiple generated forms.** Hand-maintained duplicate arrays or recipe maps are not allowed.
2. **React Native behavior is the portability floor.** Web-only selectors are optional progressive enhancement, not the source of truth.
3. **Runtime preview, static installed output.** The iframe needs all selectable profiles through small generated maps; user projects receive one resolved profile.
4. **Static class literals only.** NativeWind/Uniwind must be able to discover every generated utility. Do not build class names with interpolation at runtime.
5. **Semantic roles, not dashboard-specific magic numbers.** Components and blocks consume named roles that recipes can resolve differently.
6. **Compatibility values are not advertised capabilities.** Wire decoding and old registry paths can outlive active picker choices.
7. **Readiness is explicit.** The iframe acknowledges a revision only after its recipe, icon adapter, and font are ready or a deterministic fallback has been reported.
8. **Performance is a release gate.** No eager import of all icon packages, full style CSS, all font faces, or `/present` code is acceptable.

### 5.3 Recipe inputs and outputs

The existing `cn-*` hooks remain the stable bridge to shadcn recipes. The compiler should:

1. Read the eight canonical CSS files directly before generating anything.
2. Parse each `cn-*` rule and its `@apply` utilities.
3. Resolve a declarative marker manifest identifying whether a hook targets a container, text, icon, overlay, or block role.
4. Remove or translate native-hostile classes such as DOM data variants, `has-*`, nested SVG selectors, unsupported grids, web animation selectors, and arbitrary descendant selectors.
5. Preserve complete typography categories: `text-*`, `font-*`, `leading-*`, `tracking-*`, casing, italic, decoration, and alignment. Do not rely on the current narrow text-class heuristic.
6. Merge base classes first and profile classes second so profile rules win; consumer `className` remains last so normal component override behavior is preserved.
7. Emit:
   - static classes into each NativeWind and Uniwind registry component;
   - a small app-local map containing only hooks used by the lightweight customizer dashboard;
   - optional web enhancement CSS from the same source where the behavior is tested and does not define native semantics.
8. Fail if an active style is missing a required customizer/component hook, if any `cn-*` marker survives generated output, or if an unsupported runtime-generated class is emitted.

Replace `build-registry.cjs`'s sibling `ui/apps/v4/registry/styles` read and copy-after-build step. Public registry CSS becomes generated/debug output, never the compiler's input.

### 5.4 Resolved design-system model

A pure resolver should return one normalized object for the preview, CLI, and generators:

- normalized active preset values;
- selected style profile;
- component recipe hooks;
- block layout roles;
- typography roles;
- selected font and face map;
- selected icon library and icon defaults;
- color, chart, and radius tokens;
- migration warnings, if any;
- a catalog/profile version for cache and acknowledgement diagnostics.

Recommended role groups:

**Layout roles**

- `page.paddingX`, `page.paddingY`, `page.maxWidth`
- `grid.columnGap`, `grid.rowGap`
- `column.gap`
- `stack.xs`, `stack.sm`, `stack.md`, `stack.lg`
- `field.gap`, `fieldGroup.gap`
- `inline.gap`
- `section.gap`

**Component roles**

- card shell/header/content/footer
- button shell/text by variant and size
- input/textarea/select trigger
- badge shell/text
- checkbox and indicator
- progress track/indicator
- separator
- menu/list item
- dialog/popover/sheet content
- focus, border, and shadow treatment

**Typography roles**

- `display`
- `heading`
- `cardTitle`
- `dialogTitle`
- `body`
- `label`
- `caption`
- `metric`
- `menuItem`
- `badge`
- `button`
- `code`

Each typography role can resolve family face, size, line height, weight, tracking, and text transform. The selected `font` controls family/faces; the selected `style` controls role metrics and casing.

**Icon roles**

- default/control/navigation/status icon size
- stroke width for Lucide/Tabler
- weight for Phosphor
- inline spacing/alignment

### 5.5 Style and radius precedence

- Colors, accent, chart ramp, and dark mode remain independent preset dimensions.
- A style recipe chooses shape intent (`rounded-md`, `rounded-none`, `rounded-full`, etc.).
- The radius preset changes the numeric semantic radius scale used by token-based rounded classes.
- Explicit square or pill choices in a recipe remain intentional unless a documented global `none` policy is approved.
- Tests must cover the interaction instead of allowing radius and style classes to override one another accidentally.

## 6. Preview runtime design

### 6.1 Lightweight provider

Add a preview-only provider, for example:

```text
apps/preview/src/components/design-system/design-system-provider.tsx
apps/preview/src/components/design-system/use-design-system.ts
```

`DesignSystemProvider` receives the decoded preset and exposes the resolved profile, role helpers, semantic icon component, font readiness, and migration status. A preset update changes provider state and rerenders components; style and icons must not be implemented solely through DOM variables.

Refactor `apps/preview/src/lib/preview-theme.ts` into separate responsibilities:

- browser-safe wire decode/normalization imported from generated catalog data;
- pure design-system resolution;
- DOM color/radius/color-scheme application for web;
- font adapter loading/readiness;
- no duplicate manually maintained value arrays.

DOM classes or `data-style` may be set for diagnostics and optional web enhancement, but native-safe recipe objects are authoritative.

### 6.2 Preserve the iframe protocol

Keep the existing sequence and stable URL:

1. Next renders `/customizer-preview?preset=<initial>` once.
2. Subsequent changes use the existing `lvcn:preset` message.
3. The preview validates origin/source and decodes then normalizes the preset.
4. The provider resolves recipe, typography, icon adapter, font, color, and radius.
5. React commits the new dashboard classes/components.
6. The selected icon adapter and font report ready, or a deterministic fallback reports a warning.
7. The preview sends `lvcn:applied` for the exact revision.
8. The Next skeleton hides only for the latest matching revision.

The message may add `catalogVersion`, `normalizedPreset`, `warnings`, and `ready: { recipe, icons, font }`, but it must retain the fields the existing parent expects. Retry behavior, origin checks, and source checks remain.

Do not make the iframe URL depend on every live update and do not import `/present` modules into this route.

### 6.3 Static recipe classes

`apps/preview/src/lib/generated/customizer-recipes.ts` must contain explicit string literals for every profile/role. Components can select a map entry at runtime, but cannot construct utilities such as `` `gap-${value}` ``. Keep truly numeric values inline only where React Native APIs require them, such as `ScrollView.contentContainerStyle`, chart dimensions, or calculated widths.

### 6.4 Dashboard migration

Keep one dashboard and its lightweight local primitives. Migrate both primitive defaults and call sites:

- `Text` accepts a semantic typography role.
- `Button` resolves shell and text recipes by variant/size.
- `Card`, `CardHeader`, `CardContent`, `CardTitle`, and `CardDescription` consume card roles.
- `Input`, `Label`, `Badge`, `Checkbox`, `Progress`, and `Separator` consume their component roles.
- Replace fixed call-site typography such as `text-lg font-bold` and `text-xs font-semibold` with semantic roles.
- Replace repeated `gap-4`, `gap-1.5`, `gap-6`, `px-3`, and `-mx-3` layout decisions with stack, field, grid, and column roles.
- Keep data-visualization geometry fixed where it represents chart data, but style chart shells, labels, legends, gaps, and radii through roles.
- Add a small, natural set of semantic icons to existing cards/actions/statuses so changing icon library is visible without turning the page into an icon gallery.
- Do not create eight dashboard files or branch the full JSX by style.

Style-aware block rules should be limited to real composition differences. As an initial parity anchor, Lyra and Mira should use a tighter page/grid/column rhythm, while Maia and Sera can use more breathing room. Component recipes remain responsible for most differences.

### 6.5 Touch and accessibility behavior

Compact styles may visually use controls comparable to shadcn's `h-7`/`h-8`, but native interactive targets must remain at least 44×44 dp through `hitSlop`, a transparent wrapper, or another tested mechanism. Do not inflate visual density merely to achieve the hit target.

Also validate:

- keyboard focus visibility on web;
- no clipped text under React Native font scaling;
- sufficient contrast in light/dark modes;
- icon-only controls have accessible labels;
- decorative icons are hidden from assistive technology;
- reduced-motion behavior remains unaffected.

## 7. Semantic icon architecture

### 7.1 Manifest and normalized API

`icon-manifest.json` maps a semantic key to one tested export in each active library. Initial keys must cover all primitive internals, the customizer dashboard, and generated blocks. Representative keys include:

- `check`, `close`, `chevron-down`, `chevron-up`, `chevron-left`, `chevron-right`
- `more-horizontal`, `menu`, `search`, `settings`, `user`, `users`, `home`
- `lock`, `warning`, `info`, `success`, `error`, `loader`
- `arrow-right`, `arrow-up`, `arrow-down`, `trending-up`, `trending-down`
- `calendar`, `bell`, `credit-card`, `wallet`, `chart`, `terminal`, `plus`, `minus`

Inventory every direct Lucide import in preview primitives, `registry-src`, and `scripts/blocks` during implementation; the build must fail if any managed semantic icon lacks a mapping.

Use a normalized component contract:

- `name`
- `size`
- `color`
- `className`
- `strokeWidth`
- `weight`
- accessibility label/decorative state

Adapters translate this contract:

- Lucide uses `size`, `color`, and `strokeWidth`.
- Tabler uses `size`, `color`, and stroke width.
- Phosphor maps weight and ignores/translates unsupported stroke semantics deliberately.

Brand marks such as Apple or GitHub are fixed brand assets, not interchangeable design-system icons. Move them to a separate brand-icon path or SVG asset rather than inventing mismatched semantic mappings.

### 7.2 Preview adapters and bundle behavior

Proposed files:

```text
apps/preview/src/components/design-system/semantic-icon.tsx
apps/preview/src/components/design-system/icons/lucide.tsx
apps/preview/src/components/design-system/icons/phosphor.tsx
apps/preview/src/components/design-system/icons/tabler.tsx
```

Each adapter imports only the curated exports in the manifest. Load only the selected adapter through a bundler-tested lazy boundary; do not namespace-import an entire package and do not put all libraries in the customizer entry chunk. Cache adapter promises by library and render a stable square fallback while loading.

Pin exact tested package versions when this phase is implemented. No dependency is added as part of this plan.

### 7.3 Generated project output

Canonical components and blocks should import internal semantic icons from a generated project module rather than importing Lucide directly. The selected project's icon module contains only one library's mappings, and `lvcn init/add/apply` installs only that package.

The generic `Icon` wrapper must use a library-neutral component type instead of `LucideIcon`/`LucideProps`. Provide engine-specific interop for NativeWind and Uniwind while preserving the same public normalized props.

`lovda apply` should switch managed icon output transactionally:

1. snapshot managed files;
2. install the new selected package at the tested version;
3. replace the generated semantic icon module;
4. regenerate/reinstall managed components and blocks if required;
5. update `lvcn.json` only after success;
6. roll back files on failure;
7. remove an old managed package only when no imports remain, otherwise warn rather than deleting user dependencies.

User-authored direct imports are not silently rewritten. Documentation should explain that semantic imports are switchable and direct package imports are user-owned.

## 8. Font and typography architecture

### 8.1 Font manifest

For each retained font, record:

- active key and display name;
- `@expo-google-fonts/*` package;
- exact tested package version;
- category (`sans`, `serif`, `mono`);
- regular/medium/semibold/bold exports used by retained style roles;
- italic exports if a retained component role needs them;
- runtime family aliases for native and web;
- fallback stack;
- default style associations.

Do not claim a font is supported until all required faces load on Android, iOS, and web. If a package lacks a required face, map the role explicitly or reduce the supported weight set; do not assume browser-style synthetic weight behavior on native.

### 8.2 Preview loading

Replace the customizer's `document.createElement('link')` Google Fonts path with `expo-font`/`@expo-google-fonts` adapters that work on web and native. Load only the selected family's required faces and cache them. The provider exposes font readiness and does not acknowledge an exact preset before the selected font is ready, unless it sends an explicit fallback warning.

Font family selection and style typography are separate concerns:

- `font` selects loaded family/faces;
- `style` selects role size, line height, weight, tracking, and casing.

This is what makes component typography visibly style-dependent even when two profiles use the same family.

### 8.3 Generated templates and existing projects

Base templates should not hardcode every optional font. Add a small generated font bootstrap module and wire each SDK 54/57 root layout to wait for it before hiding the splash screen/rendering the app. The CLI writes the selected font adapter and installs only its package.

Files affected include:

- `packages/templates/nativewind/54/app/_layout.tsx`
- `packages/templates/nativewind/57/src/app/_layout.tsx`
- `packages/templates/uniwind/54/app/_layout.tsx`
- `packages/templates/uniwind/57/src/app/_layout.tsx`
- each corresponding template `package.json`
- `packages/lovdacn/src/commands/init.ts`
- `packages/lovdacn/src/commands/apply.ts`

Remove the unused hardcoded `@expo-google-fonts/instrument-serif` template dependency. Treat template uses of `@expo/vector-icons` for starter navigation as template infrastructure, not as the selectable design-system icon family.

For an existing project, use an idempotent, tested root-layout modification. If the layout shape cannot be recognized safely, generate the loader module and print exact manual integration steps instead of corrupting user code.

## 9. Registry, blocks, and templates

### 9.1 Component registry

Retain static per-style output under:

```text
apps/v2/public/r/styles/{nativewind,uniwind}/{style}/
```

Generate active style metadata from `catalog.json`. Compatibility aliases may still be emitted but must be flagged `legacy: true` and excluded from current index/pickers.

Move stable recipe markers into canonical component source or a declarative marker manifest. Avoid brittle regex guesses based only on filenames and class prefixes. Add explicit handling for text and icon targets where React Native cannot reproduce descendant selectors.

### 9.2 Block registry

Current blocks compose style-aware primitives but retain their own fixed layout classes and direct Lucide imports. Add semantic block roles to canonical block source and generate static per-style block output, or resolve those markers while producing the block registry. Do not ship a runtime eight-profile context in installed applications.

Update:

- `packages/lovdacn/scripts/build-blocks.cjs`
- `packages/lovdacn/scripts/blocks/**`
- block registry URL resolution in the CLI
- `apps/preview/src/components/blocks/**` where shared visual examples are expected to reflect a selected preset

Keep old style-agnostic block URLs as compatibility redirects/artifacts if published clients depend on them.

### 9.3 Template/install behavior

A generated project should contain:

- one selected static style recipe in its installed component source;
- one selected semantic icon adapter and package;
- one selected font loader and package;
- color/radius variables for its preset;
- no preview-only provider;
- no unselected style maps, icon libraries, or font packages.

`lvcn add` and full `lvcn apply` must use normalized active style values before selecting registry paths. Registry generation and CLI tests should cover both engines and both template layouts.

## 11. Validation plan

### 11.1 Unit and generation tests

- Preset encode/decode round-trip for every active value in every field, plus representative combinations.
- Fixed v1 codes for `default`, `new-york`, removed fonts, Expo, and Heroicons normalize to expected active values.
- Unknown versions/indices use documented failure/fallback behavior.
- Catalog-generated TypeScript and schema values match exactly.
- Recipe parser snapshots for representative hooks from every style.
- Native-safe filtering fixtures for data/has/focus/grid/descendant/arbitrary selectors.
- Typography extraction includes line height, tracking, casing, italics, and decoration.
- All required hooks exist for all eight styles.
- Every semantic icon key has Lucide, Phosphor, and Tabler mappings.
- Font manifest exposes every face required by typography roles.
- Registry generation is deterministic and leaves no diff.
- Generated files contain no `cn-*` markers, runtime class interpolation, unmanaged direct icon imports, or unexpected packages.

### 11.2 Visual matrix

Capture deterministic screenshots for:

- 8 styles × 2 color modes at a desktop viewport;
- 8 styles × 2 color modes at a mobile viewport;
- all 3 icon libraries on an icon-rich canonical state;
- all 6 fonts on a typography specimen;
- radius extremes (`none`, `full`) on square, rounded, and pill-oriented profiles.

Add metric assertions in addition to screenshots, for example:

- Nova card rhythm is tighter than Maia card rhythm.
- Lyra title/button treatment is compact and technical.
- Sera title/badge treatment uses expected uppercase/tracking.
- At least one spacing, control-size, shape/border/shadow, and typography property differs between every pair of intentionally distinct reference profiles.

Review anti-aliasing-tolerant screenshot diffs rather than relying on exact raw pixels for font rendering across operating systems.

### 11.5 Performance gates

Measure the same entry/chunk set used for the established baseline.

Hard gate for the initial/default customizer entry:

- raw: no more than 10% over 1,260,693 bytes (**≤ 1,386,762 bytes**);
- gzip: no more than 10% over 335,466 bytes (**≤ 369,013 bytes**);
- Brotli: no more than 10% over 267,845 bytes (**≤ 294,630 bytes**).

Additional constraints:

- `/customizer-preview` must not reference the `/present` heavy chunk.
- Phosphor and Tabler are separate lazy chunks, not part of the default Lucide entry.
- Each adapter imports a curated semantic subset, not a package namespace.
- Font binaries are measured as assets and loaded for the selected family only.
- All eight full recipe CSS files must not be shipped to the iframe runtime.
- Any gate breach blocks release and is addressed by reducing mappings, improving splitting, or moving work to generation—not by accepting silent regression.

### 11.6 Accessibility and interaction

- Native interactive hit area at least 44×44 dp even for visually compact controls.
- Keyboard and screen-reader navigation for all preview interactions.
- Focus indicators remain visible across styles and modes.
- Icon-only actions have labels; decorative icons are hidden.
- Text remains readable under font scaling and does not clip in compact controls.
- Color contrast checked for retained base/accent combinations.
- No preset update resets dashboard interaction state unnecessarily.

## 12. Acceptance criteria

The work is complete only when all of the following are true:

1. Selecting each retained style visibly changes density, control size, spacing, shape/borders/shadows, and component typography while colors are held constant.
2. Style changes occur through the existing message-driven iframe without navigation or reload.
3. Lucide, Phosphor, and Tabler each render every required semantic icon and visibly switch at runtime.
4. Typography roles differ by style and the six retained font families load on web/native.
5. Preview recipes and installed component/block output derive from the same canonical assets and pass parity fixtures.
6. Generated user projects include only one selected style, icon library, and font package.
7. `default`, `new-york`, Expo icons, Heroicons, and seventeen unsupported fonts are absent from active UI, prompts, randomization, schemas, and metadata.
8. Existing v1 codes and legacy configs normalize deterministically without crashes or random fallback.
9. NativeWind and Uniwind output type-checks for both supported SDK template layouts.
10. Preview Expo export and v2 production build pass.
11. The dedicated customizer entry remains inside the 10% raw/gzip/Brotli budget and does not import `/present`.
12. Dense styles retain accessible touch targets, text scaling, focus, and labels.
13. Regeneration is standalone, deterministic, and independent of the sibling shadcn checkout.

## 13. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Upstream shadcn recipe changes unexpectedly alter RN output | Vendor a pinned snapshot with provenance; sync intentionally; review generated diffs and visual snapshots. |
| CSS parser or current class heuristics lose typography/icon rules | Use declarative target metadata, focused parser fixtures, and fail on missing required hooks. |
| Web selectors have no RN equivalent | Define a documented native-safe core and explicit component props/roles; treat web-only behavior as enhancement. |
| Dynamic classes are absent from NativeWind output | Emit app-local static literal maps and add generated-bundle/render tests for every role. |
| All icon packages inflate the customizer | Curated named imports, per-library lazy modules, promise caching, and hard bundle gates. |
| Font selection flashes or uses wrong weights | Load explicit retained faces, gate acknowledgement on readiness, and test Android/iOS/web family names. |
| Compact visual controls become inaccessible | Separate visual bounds from interaction bounds using hit slop/wrappers and test 44 dp targets. |
| Alias pruning breaks old links/configs | Freeze v1 tables, normalize explicitly, keep temporary registry compatibility paths, and publish migration notes. |
| CLI icon switching rewrites user code unsafely | Manage only generated semantic modules/files; warn for direct user imports; use backup/rollback. |
| Preview and registry drift | One source/compiler, parity fixtures, deterministic generation, and CI clean-diff enforcement. |
| Adding context or adapters pulls `/present` back into the route | Keep modules under the lightweight customizer boundary and assert chunk-graph isolation in CI. |

## 14. Review checkpoints before implementation

Approval is requested for these decisions before feature work begins:

1. **Active styles:** the eight recipe-backed names only; `default`/`new-york` normalize to Vega.
2. **Default:** Vega with its named default font/icon combination.
3. **Active icons:** Lucide, Phosphor, and Tabler; Expo/Heroicons removed from current choices.
4. **Active fonts:** the six named-preset fonts; other v1 fonts hidden and normalized by category.
5. **Output model:** runtime profile switching only in preview; static selected recipe/icon/font in installed projects.
6. **Canonical source:** vendored recipe CSS plus machine-readable manifests inside `packages/lovdacn`, with generated app/CLI artifacts.
7. **Compatibility window:** preserve old style registry URLs for older CLI clients while removing them from current metadata.
8. **Performance budget:** maximum 10% regression for the customizer entry, with nondefault icons lazy-loaded.
9. **Accessibility adaptation:** preserve shadcn-like visual density while maintaining native hit targets.

After these checkpoints are approved, implementation should proceed phase by phase, with no phase advertising capabilities that have not passed its exit criteria.
